# v0.5主包合并说明

本版将v0.3主计划与已讨论的125MS/s、FIR125MHz、DMA200MHz、RingBuffer和DRFM内容实际合并；无需再手工叠加v0.4或链路审查补丁。

## 已合并

正式更新16份机器合同，包括原10份与新增bank、记录策略、量程选择、时延、回放描述符、资源6份合同（实际文件数以contracts目录和验证报告为准）。更新全部specs/Codex，导出C/SV常量和ABI偏移。新增四bank广播轮换、超窗拒绝、完整TX补零和跨文件一致性测试。

主要基线：八独立ADC；RX4→2→1和TX1→2→4复SPC全部125MHz；DMA128bit200MHz；四组×四bank×16384×64bit；正常共同选档后记录；256KiB×512 DDR槽；Gen1 ZU27DR参考速率；单HV DRFM加8TX滤波与独立校准预算。

四bank编号不再被读成固定任务：所有可用bank写滚动历史，触发保留某一bank，窗口结束停写，直接双口读出，引用归还后重新预填，无bank之间的波形复制。

## 修正的既有歧义

GSC每拍加4，原包遗漏的模块说明已同步；count至少15bit；AUX PL历史清除42输出间隔而非群延迟；原生word与复SPC分开；记录TLAST由formatter控制；普通SG不覆盖未消费槽；旧V46重复重新编号；冻结后才开始DMA服务；队列准入同时检查bank和DDR槽；TX读完继续补零输出滤波尾。

## 交付边界

原始输入在provenance归档，仅用于追溯。本版没有产生实际RTL逻辑、Vivado IP/BD、bitstream/XSA/ELF；设备封装、BSP、模拟增益/阈值、pipeline和持续吞吐等仍需真实工程确认。reports保存本轮实际测试，硬件验收保持NOT_RUN。

## 阅读与复算入口

- `README.md`：唯一活动基线和目录导航。
- `reports/merge_traceability.md`：讨论决定逐项对应合同、文档与测试。
- `reports/contract_changes.json`：与v0.3的字段级差异，157条记录。
- `reports/验证结果.md`：实际运行的77项Python测试及生成C常量编译检查。
- `codex/任务顺序.md`与根`AGENTS.md`：后续实施约束与任务门。

解压后可先运行`python tools/check_integrity.py`校验发行文件，再运行`verify.cmd`（Windows）或`bash verify.sh`（Linux）。复算会更新reports；更新后的报告时间戳不会再与原发行哈希相同，这是正常现象。
