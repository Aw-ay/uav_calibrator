# PS软件框架与上位机衔接

## 1. 推荐软件路线

先用A53裸机bring-up验证硬件边界，再使用固定版本Linux BSP构建正式采集服务。两者复用寄存器、frame和参数合同；不是同时争用同一DMA。无需初期增加R5/AMP：硬实时已经在PL，只有新增明确任务才评审R5。

Vivado导出的是硬件平台；PS软件需匹配的Vitis工具链/BSP（及需要时PetaLinux）。不能把“生成BD”当成PL+PS代码已完成。

## 2. 裸机目录建议

```text
sw/common/
  generated/calib_regs.h      从唯一寄存器合同生成
  generated/frame_format.h   从唯一frame合同生成
  calib_config.c
  frame_decode.c
  calibration_bundle.c
sw/baremetal/
  app/main.c
  board/board_clock.c
  board/board_safe_io.c
  rfdc/rfdc_setup.c
  rfdc/rfdc_mts.c
  dma/dma_sg_rx.c
  control/event_reader.c
  tests/test_registers.c
  tests/test_dma_pattern.c
  tests/test_dds_loopback.c
```

启动顺序：默认静音→UART日志→板级时钟→RFDC驱动初始化→MTS/数字特性同步→读出IP/能力/时延→准备DMA BD及buffer→使能采集→最后按任务允许TX。

驱动使用匹配BSP的RFdc API，不直接复制别代器件寄存器地址。MTS结果、target latency和校准版本保存到任务manifest。

裸机DMA使用AMD驱动SG API，正确处理BD cache flush/invalidate、对齐、所有权和中断；不同缓存属性不可混用。先以已知计数pattern验证，后接RF数据。

## 3. Linux内核层

建议一个项目设备驱动负责CSR/事件/任务接口，一个DMAengine客户端负责IQ接收，可合为一个platform driver。复用Xilinx AXI DMA controller驱动，不手写第二套BD控制器与它竞争。[A17][A18]

```text
sw/linux/kernel/
  calib_platform.c
  calib_dma_client.c
  calib_event.c
  calib_uapi.h
sw/linux/device_tree/
  calib-overlay.dtsi  # 从实际XSA/BSP绑定导出后补充
```

必须落实：

- `dma_alloc_coherent`或正确DMA mapping API取得DMA内存；用户态通过mmap/ioctl/poll使用，不能把malloc地址当物理DDR地址。
- HP0是non-coherent路径，不无依据添加`dma-coherent`；按真实互联和cache属性配置。[A14]
- 40bit地址候选必须与dma_mask、device-tree及实际分配地址一致。
- IRQ批量回收、poll等待、多buffer排队；不依赖Linux对每个pulse实时启动DMA。
- 变长帧的实际长度由已验证驱动完成信息与header交叉核查。普通DMAengine callback不应被假定天然返回所有每包实际长度信息。
- 用状态机区分FREE/KERNEL_OWNED/DMA_ACTIVE/COMPLETE/USER_OWNED，用户release后才能复用。
- error、reset和进程退出要正确取消任务、回收buffer并保存丢失范围，保持PL安全。
- 只有一个配置所有者；RFDC官方用户态驱动/UIO与自研内核访问不能同时写同一寄存器。

不要把旧DMA示例中的固定地址、缓存开关或BSP名称原样复制到RFSoC；AMD Wiki示例是可移植的原型，不是本板已认证驱动。[A17][A18]

## 4. 用户态层

```text
sw/linux/libcalib/
  device.c           打开、能力检查、版本协商
  capture.c          提交/回收capture buffers
  command.c          shadow/commit/ack
  waveform.c         DDS/AWG/burst描述符
  calibration.c      静态校准包与版本管理
  navigation.c       观测时间映射；不读取仿真真值
  recording.c        原始IQ、事件、sidecar、散列
sw/linux/apps/
  calibctl            CLI控制与状态
  calibd              任务与采集服务
  calib_capture_test  吞吐/连续性压力测试
```

板载PS只做轻量测量和慢速控制。未知参考的多径联合优化、复杂OTA估计和蒙特卡洛默认运行地面host C；不要为了“PL+PS全实现”把C的所有MATLAB函数硬塞A53或RTL。

## 5. 控制接口语义

拟议API：

- `get_capabilities()`：读真实编译功能、clock/sample-rate、位宽、bank数。
- `read_status_snapshot()`：原子读取fault、GSC epoch和队列状态。
- `configure_capture(profile)`：校验阈值、pre/post/maxPW；在IDLE提交。
- `load_waveform(inactive_bank, iq)`：检查length/CRC，再切换。
- `load_calibration(bundle)`：检查适用频率、量程、温度、版本与系数引用。
- `submit_tx_task(task)`：含绝对生效时刻、允许模式、输出限值和超时；PL可拒绝。
- `receive_frame()` / `release_frame()`：明确buffer所有权。
- `read_events()`：批量CAPTURE_PDW、回放执行和fault事件。
- `stop_and_safe()`：发请求并验证实际SAFE；不能用软件状态代替物理联锁。

接口名称是拟议规范，不是本包已实现的C函数。

## 6. 与阶段C的数据合同

保持RAW记录、CAPTURE_PDW和后来FINE_PDW分离；使用pulse_id、epoch_id、config_id和metadata_id关联。导航、温度、实际TX参考、源选择、time-quality等sidecar只保存实际观测。没有数据写UNKNOWN/NOT_AVAILABLE。

C的修正结果可以形成下一组任务提案；必须核对calibration版本、时效、限幅、合法时隙，并经授权提交。不允许未知参考盲估计直接闭环改变正在执行的PL系数。

## 7. 网络与持久存储

本体连续单档HV IQ16为1GB/s；主3档为3GB/s，加独立AUX后为4GB/s，不等于常见千兆口可持续输出。先在PS DDR吸收burst，再按SSD和网络实测服务率决定限流、片段选择或拒收策略。

具体板卡未确认，不能将旧AXRF47手册的M.2/GTR/DDR连接直接套用ZU27DR。若板级确实具备相应器件，优先匹配Linux已有PCIe/NVMe/GEM驱动。PL DDR/MIG、高速光口IP不是为了“看起来完整”而自动添加。

完整保存capture→DMA→文件→host各级sequence、bytes和drop计数。即使丢Full IQ，也保留尽可能小的event；event自身溢出也必须显式报告。

## 8. 八ADC与独立AUX接口

启动必须验证ADC_PRESENT_MASK=0xFF，并监控全部八路序号/有效性。AUX_SOURCE_SHADOW/COMMIT控制ADC3/7的SAFE_TERMINATED、REDUNDANT_EXTERNAL_MID、RF_LOOPBACK三态；不能通过该接口改变主MID数据源。切换等待真实模拟开关、稳定时间和滤波尾清除，状态未确认前不能报告AUX有效。

新增拟议API：`configure_aux_source(role)`、`capture_aux_window(window, tx_event_id)`、`read_channel_health()`。都是接口设计，不是已实现C函数。AUX单独计数丢帧，LOOPBACK来源一律禁止自动DRFM重放。主测量和AUX同时工作时，PS分别保存标校ID和来源epoch。

冗余替代必须先切到外部MID输入并校准，在脉冲边界通过既有shadow/commit提交；不能在同一脉冲途中静默用AUX替换原MID。

## 9. v0.5活动配置与接收池

C/RTL常量和ABI偏移必须从contracts生成，不能手写另一套125M参数；对应生成器属于Codex任务C01的待开发产物，本框架包不附源码。ABI版本5，最大记录131216Byte，256KiB槽×512=128MiB候选池。DMA200MHz保持；普通SG、cyclic关闭。描述符链的环形组织不允许覆盖USER_OWNED槽，软件只推进到已准备好的free槽。

configure_capture必须同时验证samples<=16384和record<=slot；pre250、post250、maxbody15000，EOP真实时间和检测延迟分离。检测上界、量程实际增益顺序和校准未配置时拒绝精密ARM，不把零默认值当有效资格。默认normal只上传共同选中H/V；三档仍并行捕获，AUX预算独立。

READER_DONE只意味着RAM可以按引用规则归还；驱动必须另核对BD实际长度、recordCRC/sequence及lost范围。一个pool只有一个驱动所有者，不能混用baremetal SG与Linux DMAengine。更新系数需pin旧任务，任务/RAW/PS槽分别释放。

核对能力报告时检查FIR125、DMA200、8ADC、8TXFIR、1HV_DRFM、4bank/组；这些是目标能力，实际CAPABILITIES只能在RTL实现验证后置位。
