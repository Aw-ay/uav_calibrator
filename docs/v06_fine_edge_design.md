# Fine 候选边沿求解硬件

2026-09-30，D07进一步完成。`fine_edge_solver`现在实际计算两点插值、局部OLS拟合、
两种方差和加权融合，不再只有相位与统计硬件。**它是单候选边沿服务，完整Fine搜索控制器和整引擎仍未完成。**

## 输入与数值规则

输入为已冻结的局部功率窗口（k-3..k+4，允许RAW边界裁剪）、点数、窗口内k偏移、
RAW相对k索引、阈值、noise及上升/下降方向。每次锁存后独立求解，结果背压时保持全部字段。
功率来自有符号16bit IQ平方和，范围0..2^31；索引是RAW相对索引，不是物理bank地址。
阈值仍由上游冻结的noise+净TOP/2产生，该模块不重新计算TOP，不重复减noise。

前端顺序累加局部矩，形成signed48的OLS slope/intercept/root numerator和signed64残差。
生成的62条固定微指令复用一个unsigned256运算单元，执行精确乘除、残差方差选择和融合。
非负比值使用最近整数、正好一半向上舍入，与冻结的符号归一化后数值规则一致。
Q32方差最小为1LSB，超出unsigned64时置VARIANCE_OVERFLOW并清valid，不饱和为伪有效边沿。
保留现有方差融合忽略协方差的工程估计政策，不声称这等于物理置信度。

`fine_wide_math`每拍只穿过32bit进位链；加/减、位串行乘法和恢复除法均有显式状态机。
除法保留257位试减的高位信息，正确处理unsigned256全范围和舍入溢出。
减法borrow只在微程序的方差比较步骤作为合法分支条件，其余算术故障均使候选结果无效。
复位/取消同时清除前端、微程序及正在计算的算术单元，不能晚到发布旧结果。

## 三层验证

1. 独立数学参考仍为 `fine_fixed.edge_pair_q16`，使用有界精确有理数。
2. `fine_edge_program.candidate_reference`直接执行有限宽整数微程序，并推导精确拍数；
   与独立参考逐字段比对，生成RTL输入/期望。生成包一致性也有检查。
3. RTL同时检查数值与请求到结果的拍数；测试包括背压、前端/乘法/除法/舍入/持有结果时取消及冷复位。

共享算术255组向量覆盖256bit极值、溢出、借位、零除数、正好一半舍入等。
完整候选边沿320组向量（237有效）逐位且逐拍匹配，覆盖正负斜率、短窗/边界裁剪、
随机功率、随机近线性斜坡、错误交点、拟合根越界、零noise及方差溢出。
Vivado2025.2 XSim也通过相同320组及取消/复位测试。
既有Fine数值、CORDIC、缓存、累加器和reader组合纳入本阶段13个相关回归入口。

## 延迟与吞吐限制

加减8拍；乘法258+16×乘数置位数（最多4354拍）；除法截断2561拍，
舍入2570或2578拍，零除数当拍无效返回。这些为握手接受至valid的周期数，不含结果等待消费者。

320组中最大候选延迟28399拍=141.995µs；这不是最坏输入证明。
由微指令和运算最大拍数得到保守上界135303拍=676.515µs，仍只包括一个候选服务。
FinePass现在可用该有限宽模型返回的真实求解拍数，串行处理H/V候选，暂停采样读入和退休。
256点普通脉冲示例4个候选共106812求解拍=534.06µs；含扫描的模型总107327拍，局部缓存峰值32。
振铃例7个候选（含快速无效退出）共79909求解拍，缓存同样32。

因此本阶段证明数值与有限存储因果关系，**不证明Fine作业吞吐满足高PRF**。
三档顺序处理还要乘以相应工作量，加缓存查询、控制、LS FINALIZE、排队和释放时间。
后续需要将这个预算用于analysis引用、队列容量、过载丢弃策略，必要时优化求解器。
不得把Fine队列压力变成等待Fine完成后才允许已合法DRFM回放，也不能暗中二次读取RAM。
