# Codex分阶段任务设计

本文是开发分工规格，不表示这些任务已执行。真正实现须先确认板级配置与数值模型。

|任务|范围|主要产物|交付门|
|---|---|---|---|
|C00|核对板卡/BSP/版本/PLL/RFDC真实接口|board profile、clock/port表、阻塞项清单|所有关键参数有来源或明确未确认|

|C03|搭平台BD壳|PS+RFDC+CSR+DMA+测试流+安全零值|BD合法且默认不TX|
|C04|实现CSR、原子配置、GSC、event|RTL和协议TB|异步更新/快照/异常全部通过|
|C05|实现native adapter与D8|RTL wrappers和定点向量|抽取/位序/过载标志正确|

|C09|DDS/AWG与TX插值/adapter|波形RTL、幅相/包络测试|从PS设置到DAC完整速率链闭合|

## 每个任务必须回答

- 输入输出、clock/reset、signed/bitpoint、valid/ready和latency是什么？
- 能否永久接受ADC速率？谁有权停数据或释放bank？
- 参数什么时候生效？是否被pending replay引用？
- 软件看见的成功状态来自计划、执行、DMA完成还是host验真？
- MATLAB对照使用哪一commit、哪一个固定点格式和哪一系数文件？
- 测试实际运行了吗？工具缺失/失败是否明确报告？

## 拟议实现工程树

```text
calibrator-plps/
  AGENTS.md
  contracts/
  hw/boards/<confirmed-board>/    board.json、vendor_preset、XDC、clock_config
  hw/tcl/                        create_ip/create_bd/build/export
  hw/ip/                         锁定XCI或IP生成脚本
  rtl/frontend/                  adapter、overload、FIR wrapper
  rtl/capture/                   detector、qualifier、banks、PDW
  rtl/replay/                    descriptor、scheduler、reader
  rtl/arithmetic/                scale、cal、fraction、matrix
  rtl/source/                    DDS、burst、AWG、MUX
  rtl/backend/                   interpolation、DAC adapter
  rtl/control/                   CSR、CDC、events、interlock
  rtl/monitor/                   TX reference
  rtl/time/                      GSC、PPS和epoch
  tb/unit/  tb/system/  tb/vectors/
  sw/common/  sw/baremetal/  sw/linux/
  tools/                         合同生成/日志验证/抓取解析
  reports/                       独立真实工具证据
  build/                         可重建产物，不是唯一源文件
```

不要先创建几十个无逻辑的空模块并声明框架能工作。优先一个可独立验证的纵向闭环，再按合同替换功能模块。
