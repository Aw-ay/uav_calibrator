# v0.6 DRFM / Fine / DMA implementation plan

Execution: in this thread, no agents/windows and no approval pauses, per user authorization.

Goal: implement the supplied v0.6 package against the current local branch, retaining
stage 22–27 AUX, task Doppler and counter/BSP work absent from the package's GitHub base.
Spec: `docs/releases/v0.6_DRFM_FINE_DMA/README.md` and its contracts/task sequence.
Tech: SystemVerilog, Vivado 2025.2, Python independent golden models, A53 C.

## Constraints and migration decisions

- RAW ABI stays 5; GSC stays 2 ns, RF clock 125 MHz, B port 200 MHz.
- Six pre-existing modified RTL files and rtl/chat.rapidgpt are protected by
  reports/v06_external_baseline.json and build/v06_external_baseline/ backups.
- Do not wholesale replace contracts: the supplied package predates local AUX
  opcodes 22–24 and task Doppler fields at bytes 136–167. Preserve these extensions.
- Fine transport contract revision 2 allocates PEEK=25 and POP=26; IRQ bit5
  reservation must be checked against the actual gateway before integration.
- Versioned package is immutable design input; implementation contracts only change
  as the corresponding migration becomes active. Explicit migration status prevents
  mistaking a new target document for implemented functionality.
- Physical binding remains external and safe when unbound. No board is connected.
- BMG latency must be measured using the generated IP simulation, not inferred.
- No FD in the eventual active replay path, no normal A-port scan dependency,
  and no 64-bit serialization in the eventual active DMA path.
