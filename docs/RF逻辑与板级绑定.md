# RF 逻辑与板级绑定

用户已确认：最终 RF 前端资料缺失不构成数字设计交付的前置阻塞。本文件替代历史进度中将 H/V 映射、增益实测值和联锁接线笼统作为 PL/PS 开发阻塞的表述。

核心交付必须完成逻辑 H/V 三档资格与共同选档、校准执行及表格式、联锁状态机、寄存器和 PS 接口、版本一致性与 TB。核心接收逻辑通道、校准参数、规范化的请求/反馈，不包含实物引脚号和控制编码。现有未实现模块仍须实现；建立此边界不代表这些模块已经完成。

板级适配负责逻辑通道到物理 ADC/DAC 的映射、控制码、实测增益、电平极性、GPIO 约束、稳定时间、PA/TR 先后顺序与尾部保护时间。运行时参数通过校验后的配置提交；引脚约束在构建时生成，不能当作可运行时写入的普通寄存器。

板级合同位于 `hw/boards/zu27dr/rf_binding.json`，当前明确为 UNBOUND，未知值使用 null，不使用虚假的零增益、零等待或默认有效引脚。该文件是绑定入口，尚不是完整校准表二进制格式。

未绑定状态不得使真实 RF 输出获得许可，也不得报告物理校准有效。数字逻辑可在独立 TB 中使用明确标记的模拟绑定，完成所有状态转换、参数边界及错误路径验证。模拟绑定不进入生产默认配置；逻辑极性适配不等同于已经验证断钟后的物理安全行为。

后续验收包括：不同模拟控制码/极性获得相同逻辑行为；真实增益顺序变化时正确选档；未绑定或参数无效时拒绝 RF 许可；脉冲中配置更新不撕裂；排队任务引用旧版本时不能被覆盖；时序参数零值、越界及不满足先后关系均按正式合同处理。校准表须定义定点格式、单位、频率/温度适用域、版本与有效性，并与 SV/C 解析同源生成。

硬件阶段再填入有证据的绑定参数，进行引脚、极性、控制顺序、断钟关断及实际增益验证。RF 时钟、SYSREF 和器件速度等级属于平台问题，仍单独核验。
